本說明書說明如何把「土建工程問題原因解析與對策研擬」技能安裝為 Claude Project。安裝後，於該 Project 內上傳工地照片，Claude 即依 ce-defect_SKILL.md 的固定流程輸出：問題序號標註圖、原因分析、5×5 風險矩陣、四層處理對策，以及 HTML 技術報告與 HTML 圖文簡報。

介面名稱說明：claude.ai 介面文字會隨版本調整，本說明以功能描述為主，括號內為常見的中英文名稱；實際名稱不同時，請以相同功能的選項操作。安裝建議使用電腦瀏覽器或桌面版 App，安裝完成後手機 App 可直接使用該專案。

2事前準備

  • 已登入 Pro、Max、Team 或 Enterprise 方案的 Claude 帳號（Projects 與程式碼執行功能依方案而定）。
  • 開啟「程式碼執行與檔案建立」（Code execution and file creation）：設定 → 功能（Capabilities）。未開啟時 Claude 無法執行 Python 標註與產出檔案。Team／Enterprise 帳號若看不到此選項，請洽組織管理員於管理設定中開啟。
  • 將 zip 下載並完整解壓縮；請勿直接上傳 zip 檔。
  • 確認 11 個檔案皆在，檔名未被系統改動（例如重複下載被加上「(1)」）。

3建立 Project

步驟 3-1　開啟 claude.ai，於左側欄點「專案（Projects）」。
步驟 3-2　點「＋ 新專案（New project）」，名稱輸入：土建工程問題原因解析與對策研擬；說明欄可填「上傳工地照片進行缺失原因解析、風險評估與對策研擬」。
步驟 3-3　點「建立專案（Create project）」，進入專案頁面。

4貼上專案指令

步驟 4-1　點下方指令框的「複製」按鈕（內容與 project_instructions.md 相同）。
步驟 4-2　在專案頁面找到「指令（Instructions）」區塊，點「設定專案指令（Set project instructions）」或編輯圖示。
步驟 4-3　貼上全文，須貼上全文，不可刪減；原有內容須先全選刪除。
步驟 4-4　點「儲存（Save instructions）」，未儲存則指令不生效。
# 土建工程問題原因解析與對策研擬（Claude Project 指令）

你是台灣土建工程缺失診斷助理。使用者上傳工地或既有結構照片時，一律依專案知識 `ce-defect_SKILL.md` 的工作流程執行：標註問題序號、原因分析、5x5 風險矩陣、四層對策，並輸出繁體中文 HTML 技術報告與 HTML 圖文簡報。全程使用繁體中文與台灣工程用語（品質、資料、場鑄、耐震）。

## 執行規則

1. 每次分析前先讀 `ce-defect_SKILL.md`，再依其「參考檔索引」讀取所需的 `ce-defect_references_*` 檔案。
2. 標註不先詢問：將 `ce-defect_references_annotation_toolkit.md` 的 Python 程式寫入沙盒執行，交付檔存到 `/mnt/user-data/outputs/`。
3. HTML 報告與簡報依兩個範本檔的完整內容寫出，結構、class 與 CSS 不得更動，照片以 base64 內嵌。
4. 影像顯示立即危險時，回覆第一段先寫緊急警示與立即措施。

## 證據與引用紀律

- 每項陳述標示證據等級：[E1 觀察]、[E2 推論]、[E3 待驗證]、[E4 使用者提供]。
- 規範條次與數值只在使用者提供原文、網路查證附連結或使用者確認後引用，否則標 [待查證]。
- 風險準則寫「依本報告採用之風險評估準則」，修復工法寫「工程實務經驗」，不得冒稱規範。
- 不同工程類別（建築、橋梁、道路、排水、隧道）之門檻值不得互相套用。
- 無單價時不編造金額；無比例尺時不給精確尺寸。

## 範圍

本專案只做依影像之初步判讀與對策建議，不取代現場調查與試驗；修復與補強設計須由專業技師依調查結果決定並簽證。
指令只負責「啟動」：完整流程寫在專案知識 ce-defect_SKILL.md，指令要求 Claude 每次先讀該檔。因此第 5 節的 10 個檔案缺一不可。

5上傳專案知識

步驟 5-1　在專案頁面找到「專案知識（Project knowledge）」區塊，點「＋」或「新增內容」，選「從裝置上傳（Upload from device）」。
步驟 5-2　進入解壓縮後的資料夾，選取 ce-defect_ 開頭的 10 個檔案（可多選）。不要上傳 project_instructions.md。
步驟 5-3　等待上傳完成，確認專案知識清單共 10 個檔案、檔名正確。

勿與其他技能混用：專案知識中若有其他技能的舊檔，請移除，以免流程互相干擾。

7日常使用方式

7-1 提供資訊越完整，判讀越準確

上傳影像時建議一併說明：工程類別（建築、橋梁、道路、排水、隧道、大地）、構件與部位、工程階段、拍攝日期、環境條件、已知施工紀錄。同一缺失拍「全景」與「近照」各一張，近照旁放比例尺或裂縫比對卡。

7-2 常用提示語

分析這 3 張照片的所有缺失，依風險等級排序，產出報告與簡報。
我補充資訊：澆置當日最高氣溫 34 度，下午 3 點才開始灑水養護。請更新編號 2 的原因分析與風險評分。
請把編號 3 的規範依據上網查證，附上連結後更新參考文獻。
請改出 PowerPoint 版簡報。

7-3 輸出檔案的使用

  • 技術報告：下載 defect_report.html，以瀏覽器開啟後可列印或另存 PDF（A4）。照片已以 base64 內嵌，單一檔案即可轉傳。
  • 圖文簡報：下載 defect_slides.html，方向鍵或點擊畫面換頁；列印選「橫向、無邊界」即可每頁一張輸出 PDF。
  • 報告標示「初評版」者，補充資訊或試驗結果後，請要求 Claude 更新為「定稿版」。

8疑難排解

#症狀可能原因處理方式
8-1只有文字描述，沒有標註圖未開啟程式碼執行，或未執行 Python確認第 2 節設定已開啟；輸入「請依 annotation_toolkit 寫入沙盒並執行標註」。
8-2標註框位置偏移座標估計誤差輸入「請先產生格線圖並檢視，重新讀取編號 N 的座標後重繪」。
8-3未依流程、未用分類代碼或風險準則未讀取專案知識開新對話並輸入「請先讀取 ce-defect_SKILL.md 與相關參考檔再分析」；確認 10 個檔案都在專案知識中。
8-4HTML 報告照片不顯示照片未內嵌輸入「請用 data_uri() 以 base64 內嵌照片後重新輸出 HTML」。
8-5報告版面與範本不同未依範本全文寫出輸入「請依 ce-defect_references_report_template.html 全文寫出，結構與 CSS 不得更動」。
8-6回覆中斷或過長單次輸出長度限制輸入「繼續」；問題多於 6 項時，要求「先出報告，簡報下一則再出」。
8-7出現規範條次或單價但未附來源未遵守引用規則輸入「請將未查證之條次與金額改標 [待查證]」，並以網路搜尋查證附連結。
8-8無法上傳影片對話可能不支援影片檔依時間碼截圖，以照片上傳。
8-9標註圖中文變方框沙盒缺中文字型屬正常設計：影像內只放數字，中文說明在圖外清單與報告中。
8-10手機 App 找不到專案指令或知識上傳手機版介面不同改用電腦瀏覽器（claude.ai）或桌面版 App 完成安裝，之後手機可直接使用該專案。

9更新與維護

  • 更新指令：於專案指令欄先全選刪除舊內容，再貼上新版全文並儲存；更新後請開新對話。
  • 更新專案知識：先刪除舊檔，再上傳同名新檔，避免新舊版本並存。
  • 補充規範條文：取得規範原文後，將查證過的條文併入 ce-defect_references_standards_index.md，並註明版次與條次。
  • 跨平台一致：本套件與 Gemini Skill（ce-defect.zip）、ChatGPT Project 套件共用同一份參考內容；修改任一平台的參考檔時，請同步更新其他平台。

10使用限制

  1. 本工具僅依影像作初步判讀，無法量測裂縫寬度、深度、活動性、內部空洞、鋼筋斷面損失或混凝土強度。
  2. 風險矩陣分級為本套件採用之預設評估準則（參考 ISO 31000、IEC 31010 概念），非規範條文；機構另有風險政策時應以機構政策為準。
  3. 修復工法為工程實務經驗整理；修復與補強設計須由依法登記之專業技師依現場調查結果決定並簽證。
  4. 規範條次與數值僅於使用者提供原文、網路查證附連結或使用者確認後引用，其餘標示 [待查證]。
